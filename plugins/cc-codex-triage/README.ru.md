# плагин cc-codex-triage

[English](README.md) · [Español](README.es.md) · **Русский**

Постоянные именованные треды Codex CLI для открытого кросс-агентного триажа в Claude Code.

## Что он даёт

- `/ask [--oneshot] <вопрос>` — информационные вопросы в постоянном треде `ask` (read-only sandbox). «Как тут работает X», «есть ли уже Y».
- `/review [--lens <name>] [--thread <name>] [--once] [--oneshot] [--cap N] [--model <m>] [--effort <e>] [--background] [--json] [--continue] <текст>` — критика в треде review; **по умолчанию итерирует до APPROVE** (диспатч → исправить → re-review, пока не APPROVE или не исчерпан `--cap` раундов), `--once` — один проход. Линзы (lenses): correctness (по умолчанию), security, performance, architecture, ux, quick. Тред по умолчанию привязан к ветке (`review-<branch>`). Вставленное чужое ревью автоматически оборачивается в Judge-mode как один классификационный проход (без цикла). `--model`/`--effort` задают модель/уровень reasoning effort, применяются только при первом диспатче или при `--oneshot` (resume сохраняет модель/effort треда стабильными и выдаёт WARN, если передать их снова). `--background` диспатчит в отсоединённом (detached) режиме и возвращает ход, не дожидаясь ответа (подразумевает один проход, без цикла; использует флаг драйвера `--detach` — диспатч выполняется в собственной сессии процессов и переживает зачистку процессов harness'ом, а ответ ложится в лог треда). `--json` возвращает структурированный вывод (`schemas/review-output.schema.json`, нужен `codex` ≥ 0.142 + `jq`) вместо прозы, рендерится в человекочитаемый вид и автоматически записывается в ledger с оценкой уверенности по каждой находке; он не может снять гейт `/autoreview` в текстовом режиме. Находки пишутся в машиночитаемый, fail-closed ledger (`<thread>.findings.jsonl`, нужен `jq` — битый ledger отвергается и читателями, и писателями: его не отрендерят пустым и в него не допишут); `--continue` пересобирает следующий раунд из ещё открытых находок + дифф с момента последнего APPROVE.
- `/plan [--lens <name>] [--thread <name>] [--once] [--oneshot] [--cap N] [--model <m>] [--effort <e>] [--background] <план>` — стресс-тест плана в треде plan; **по умолчанию итерирует до APPROVE**. Линзы: stress-test (по умолчанию), pre-mortem, devils-advocate, alternatives, adr. Линзы плана теперь завершаются машиночитаемым вердиктом (`APPROVE | REQUEST_CHANGES | COMMENT`). `--model`/`--effort` задают модель/уровень reasoning effort, применяются только при первом диспатче или при `--oneshot` (resume сохраняет модель/effort треда стабильными и выдаёт WARN, если передать их снова). `--background` диспатчит в отсоединённом (detached) режиме и возвращает ход, не дожидаясь ответа (подразумевает один проход, без цикла; использует флаг драйвера `--detach` — диспатч выполняется в собственной сессии процессов и переживает зачистку процессов harness'ом, а ответ ложится в лог треда).
- `/reply [thread] <директива>` — Claude Code отвечает обратно в активный тред (ответить на вопрос, выполнить запрошенное действие инструментом, оспорить находку).
- `/debate [--rounds N] [--thread <name>] <вопрос>` — структурированное многораундовое разногласие между Claude Code и Codex по какому-то решению, каждый обмен виден пользователю, заканчивается честным синтезом (остаточные разногласия проговариваются, а не замазываются).
- `/autoreview on|off|status` — при взведении, если в ветке уже есть изменения, оно ревьюит их сразу (без ручного `/review`); затем Stop-хук блокирует любой будущий ход с непроверенными изменениями кода, пока ревью Codex не достигнет APPROVE, **заработанного после взведения** (устаревший APPROVE с прошлого взведения не считается), либо пока не исчерпан лимит раундов. Защита от разгона: численно валидируемый лимит раундов — жёсткий терминатор (битое состояние fail-open), APPROVE — релиз по успеху, а привязка к ветке+грязному дереву держит его в стороне от посторонних ходов. Взведённые гейты **автоматически истекают через 14 дней** — устаревший гейт на давно влитой ветке снимает себя сам, вместо того чтобы сработать заново при повторном использовании имени ветки.
- `/autoplan on|off|status` — то же, что `/autoreview`, но для документов-планов: при взведении, если `docs/plans/**` уже изменён, оно сразу стресс-тестит их; затем блокирует любой будущий ход, меняющий документы-планы, пока тред плана не увидит диспатч после взведения (обычно ваш стресс-тест через `/plan`; гейт ловит рост лога, а не идентичность команды). Та же семантика лимита и автоматического истечения через 14 дней.
- `/thread [--oneshot] <name> <сообщение>` — произвольные именованные треды (прямой проброс без обрамления).
- `/thread-list` — активные треды + раунды, размер лога, последняя активность.
- `/thread-new <name> [сообщение]` — принудительный сброс треда (теряет память).
- `/status` — read-only вид на один экран: ветка, грязное дерево, взведённые гейты (с предупреждениями stale-branch / pre-0.5 / missing-target), последний вердикт по каждому треду, статус gitignore и версия Codex CLI против требуемого минимума.
- `/cleanup [--apply]` — находит устаревшие/pre-0.5 взведённые гейты и осиротевшие логи тредов; по умолчанию dry-run, `--apply` **архивирует** их (никогда не удаляет, обратимо).
- `/review-dispute <id> <почему>` / `/review-accept <id> --reason` / `/review-defer <id> --issue` — закрыть зарегистрированную находку ревью по её id (ложноположительная / принятый компромисс / отложена в отслеживаемый issue), чтобы она ушла из списка открытых с аудит-следом, а не была тихо потеряна.
- Skill `codex-triage` документирует маршрутизацию, обрамление Judge-mode, правила анти-капитуляции в дебатах, валидацию входящих находок Codex (проверь перед тем, как применять — не штампуй ради снятия гейта), правило «чинить-окрестность» и модификатор `--oneshot`.

Каждая команда по умолчанию держит постоянный тред Codex; `--oneshot` делает любую из них одноразовой (`codex exec --ephemeral`, состояние не сохраняется). **Одна задача = один тред**: `/review` и `/plan` по умолчанию используют тред, привязанный к ветке (`review-<branch>` / `plan-<branch>`, напр. `review-main` на `main` — без особого случая для main), так что каждая ветка и её соответствующий гейт остаются изолированными; передайте `--thread <topic>`, чтобы разбить дальше, или `--thread review` для общего.

## Чем он отличается от альтернатив

| | Этот плагин | `hamelsmu/claude-review-loop` | `dementev-dev/adversarial-review` |
|---|---|---|---|
| Сессии Codex | **Постоянные через `exec resume`** | Каждый раз новые | Постоянные через `exec resume` |
| Лимит раундов | **Открытый (ограничен только в гейтах `/autoreview`/`/autoplan`)** | 1 | 5 (approve/revise) |
| Назначение | **Итеративный диалог-триаж + опциональный гейт само-проверки** | Многоагентное ревью в один проход | Цикл approve/revise |
| Вывод | Markdown-поток, как есть | Сводный Markdown-файл | JSON + Markdown + литерал VERDICT |

Используйте его, когда разговор будет итеративным. Используйте `claude-review-loop` для одного исчерпывающего ревью. Используйте `adversarial-review`, когда нужен жёсткий гейт pass/fail после ограниченного числа раундов.

## Предварительные требования

- CLI `codex` ≥ 0.137.0 (`npm install -g @openai/codex`) — версия, на которой проверены семантики resume/`--ephemeral`; более старые CLI могут работать, но не тестировались.
- `/review --json` требует `codex` ≥ 0.142 (поддержка `--output-schema`) и `jq`.
- `~/.codex/config.toml` с моделью, на которую у вас есть права. Переопределение на вызов: `CC_CODEX_FLAGS="-m gpt-5.5 -s read-only"`. Ограничение: строка флагов разбивается по пробелам, поэтому значения отдельных флагов не могут содержать пробелы.
- По одной сессии Claude Code на репозиторий за раз: состояние тредов под `.claude/codex-threads/` не блокируется, поэтому две одновременные сессии, диспатчащие один тред, могут гонять счётчики/лог (выигрывает последний записавший).

## Где живёт состояние

- `.claude/codex-threads/<name>.id` — сохранённый UUID сессии Codex для треда.
- `.claude/codex-threads/<name>.log` — append-only аудит-лог пар prompt/ответ.
- `~/.codex/sessions/rollout-*.jsonl` — собственные rollout-файлы Codex (управляются Codex CLI).

Плагин никогда не удаляет rollout-файлы Codex. `/thread-new` лишь очищает локальный указатель.

## Примитивы безопасности

- **Никакого тихого нового exec при сбое resume.** Если `codex exec resume` падает, драйвер выходит с кодом 4 и просит вас явно сделать `--new`. Ваша уверенность «Codex это помнит» никогда не ломается молча.
- **Страж мутации версионируемых файлов.** Драйвер снимает снимок `git status --porcelain` до/после каждого диспатча в Codex и предупреждает при расхождении. Поставьте `CC_CODEX_TRIAGE_STRICT=1`, чтобы сделать это фатальным. Запускайте с `CC_CODEX_FLAGS="-s read-only"` для тредов чистого ревью.
- **Никакого `--last`.** Треды привязаны к сохранённому UUID; если он пропал, следующий вызов стартует с нуля, а не с «того, что недавно трогали в `~/.codex/sessions/`».

## Обрамление Judge-mode

Когда вы вставляете находки другого агента в `/review`, команда оборачивает prompt как оценку третьей стороны, а не как последовательное опровержение. Эмпирически (arXiv 2509.16533, EMNLP 2025 Findings) это снижает уровень угодливой капитуляции с 23,5–80,3 % в 1,5–2 раза.

## Установка

```
/plugin marketplace add clicktronix/cc-codex-triage
/plugin install cc-codex-triage@cc-codex-triage
```

(Суффикс `@cc-codex-triage` — это имя marketplace: `plugin@marketplace`.)

Команды плагина **пространственно именованы** (namespaced) под плагином. Вызывайте их как
`/cc-codex-triage:review`, `/cc-codex-triage:ask` и т. д. Короткая форма `/<name>`
тоже работает для имён, не сталкивающихся со встроенными, — но `/review` и
`/plan` заняты собственными командами Claude Code, поэтому для этих двух используйте форму с namespace.

## Область: однонаправленно (Claude Code → Codex CLI)

Это плагин **Claude Code**. Его slash-команды вызывают CLI `codex`
через встроенный драйвер. Он намеренно не упакован как плагин Codex
(`.codex-plugin/`) — Codex'у нечего запускать; Codex здесь вызываемый, а не
хост. Если вы хотите, чтобы Codex *хостил* skills — это другой артефакт.
