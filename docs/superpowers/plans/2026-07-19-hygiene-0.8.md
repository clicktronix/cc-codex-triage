# Hygiene 0.8 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close six state-hygiene gaps surfaced by a 2026-07-19 audit of real thread-state dirs across six production repos (marqa agent/platform/analyzer + container root, stokli frontend/backend): gates that never expire, driver state written outside the repo root, `/reply`'s misaligned default thread, `last-error.jsonl` files that outlive their failures, `/cleanup` blind to two stale-state classes, and background dispatches dying to harness process-reaping.

**Architecture:** Five independent tasks plus a release task. Tasks 1, 2, 4, 5 touch bash (driver / hook / cleanup) and extend the existing regression harnesses (`tests/driver-regression.sh`, `tests/hook-regression.sh`). Task 3 is markdown-only (`reply.md`). Task 5 (cleanup) executes AFTER Task 4 (detach) because the cleanup file-sets must include the detach sidecar Task 4 introduces. Every change is fail-open where it gates existing flows and fail-closed where it writes state.

**Tech Stack:** bash 3.2 (macOS floor) + POSIX tools, `python3` (already ubiquitous on the macOS floor) only as the `setsid` fallback, markdown command files, plugin manifest JSON.

## Global Constraints

- **Portability:** macOS bash 3.2.57 + Linux; no GNU-only flags without BSD fallback (see `lib.sh:_mtime`).
- **Fail-open on gating, fail-closed on writes:** a malformed/missing `armed_at` must never hard-block a turn; a refused dispatch must never leave partial state.
- **Backward compatible:** armed files written by ≤0.7 (no `armed_at`) keep working without TTL; bare `review`/`plan` threads remain reachable by explicit name.
- **Commit convention:** short imperative subjects. **No `Co-Authored-By` trailer, no Claude attribution.**
- **Version:** behavior fixes + additive flags → minor bump `0.7.0 → 0.8.0`.

## Design decisions (resolved defaults — override at plan review)

| # | Decision | Chosen default | Why |
|---|---|---|---|
| D1 | Gate TTL | `armed_at=<epoch>` written at arming. The Stop hook runs a **TTL pre-pass over BOTH armed files** (autoreview + autoplan) BEFORE any gate evaluates branch/dirt: each file with numeric `armed_at` older than **14 days** is `rm -f`'d with a stderr note, then evaluation **continues** (never early-exits) to the surviving gates. Missing/malformed/future `armed_at` → TTL skipped for that file (fail-open). `rm` failure → treat as expired anyway for THIS turn's gating (do not block on an unremovable stale gate), warn loudly. | A month-old gate re-firing on a reused branch name is the audited hazard. Pre-pass (not inline `allow`) because `allow` exits the whole hook and the gates are evaluated sequentially — inline handling would suppress or orphan the second gate in all four expiry/freshness combinations. |
| D2 | Repo-root anchoring | For persistent modes the driver derives the anchor as `git -C "${CLAUDE_PROJECT_DIR:-$PWD}" rev-parse --show-toplevel` — the RESOLVED repo root, never the raw candidate. Resolution failure (unset var + no repo; var pointing at a non-repo dir; var pointing at a nonexistent path) → **exit 7** with a message naming the candidate and the fixes (cd into a repo / fix CLAUDE_PROJECT_DIR / use `--oneshot`). A candidate inside a repo subdirectory resolves UP to the root — driver and hook state can no longer split. `--oneshot` keeps its no-state exception (temp diag only). | Closes all three audited ingress paths: pwd fallback into a non-repo container (marqa incident), trusted-but-wrong env var, and subdir-anchored state the hook can't see. |
| D3 | `/reply` default thread | Same rule as `/review`: `review-<branch-slug>`. Fallback chain when no thread named: slug thread exists → use it; else bare `review` exists → use it WITH a one-line warning ("legacy default thread — consider a per-task thread"); else exit-6 path unchanged. | Aligns the two commands' defaults; keeps old repos working; the warning is the migration nudge. |
| D4 | `last-error` lifecycle | Driver: the moment the codex process exits **0**, `rm -f` the thread's previous `last-error.jsonl` — BEFORE UUID extraction, so a UUID-extraction failure (which deliberately writes a fresh diag even on exit 0, `codex-thread.sh:272`) lands in a clean slot and is never erased by its own dispatch. On failure paths, cap the stored diag to the **last 64 KB** (`tail -c 65536`). | "last-error" must mean the LAST error; the deletion point matters — deleting at log-append time would erase the fresh UUID-failure evidence the driver just wrote. |
| D5 | `/cleanup` new classes | (a) **stale last-error**: diag whose thread has no `.id` (orphan) or whose `.log` is newer (recovered) → archivable. (b) **dormant threads**: `--older-than <days>` (integer **≥ 1**, validated) lists/archives whole thread file-sets. A thread's file-set = `id, log, log.1, rounds, findings.jsonl, scope, approved, last-error.jsonl, detach-output, active` — every known member, deduplicated. **Safety rails:** (1) **active lease** — the driver writes `$STATE_DIR/<t>.active` containing its PID for the whole dispatch (created at dispatch start, removed by the combined EXIT cleanup; a detached child holds its own lease since the re-exec'd child IS the driver); cleanup skips any thread whose `.active` names a **live** PID (`kill -0`), and treats a dead-PID lease as absent (it joins the archivable set) — this closes the in-flight-dispatch race that mtime checks cannot see (a resume waiting inside `codex exec` writes nothing until it returns); (2) threads named by either armed gate's `thread=` are excluded; (3) immediately before moving each set, re-stat its newest mtime and skip the thread if it changed since detection (cheap second rail); (4) generic `review`/`plan` stay list-only. | mtime re-stat alone is provably insufficient: a slow resume reads the old `.id`, waits minutes inside Codex, and touches nothing — cleanup would archive under it and the returning child would split state. A PID lease is the minimal ownership mechanism shared by driver and cleanup; no full lock subsystem needed. |
| D6 | Background resilience | New driver flag `--detach` (incompatible with `--oneshot`): persist the stdin prompt to a tmpfile, then re-exec the dispatch in a **new session**: `setsid` binary if present, else python3 with `os.setsid()` — **no `--` separator** (with `-c`, CPython sets `sys.argv[0]='-c'`, so the exec target is `sys.argv[1]`): `python3 -c 'import os,sys; os.setsid(); open(sys.argv[1],"w").write(str(os.getpid())); os.execvp(sys.argv[2], sys.argv[2:])' "$READY_FILE" bash "$0" ...`; neither available → **refuse with exit 8**. Plain `nohup` alone is NOT an accepted fallback (shields only SIGHUP, not group-targeted SIGTERM/SIGKILL — the audited reaping mechanism). **Readiness handshake:** the child proves session creation by writing its PID to `$READY_FILE` only AFTER `setsid()` succeeded (the setsid-binary path wraps as `setsid bash -c 'echo $$ > "$READY"; exec bash "$0" ...'`); the parent polls the ready file with a **bounded wait (5s)** and only then prints `DETACHED pid=<pid> output=<thread>.detach-output — poll the thread log for the next 'round=' header` / on timeout reports failure with a nonzero exit — startup failures never masquerade as DETACHED. Child: appends the reply to the thread `.log` as normal (marker contract untouched); raw stdout/stderr goes to sidecar `$STATE_DIR/<thread>.detach-output` (suffix chosen to avoid colliding with the audit log of a legally-named thread `<t>.detach` — dots are allowed in thread names). Prompt tmpfile + ready file removed via the **combined** cleanup function (see Task 4 — the driver already has an EXIT trap; a second `trap ... EXIT` would replace it). `review.md`/`plan.md` `--background`: recommend `--detach` + log-polling; keep harness `run_in_background` as documented fallback with its reaping caveat. | A new session is the only thing that survives group kill on the macOS floor where the `setsid` binary is absent — python3 supplies `os.setsid()`. The handshake closes the spawn-window race AND the false-DETACHED failure mode; the argv fix matters because `--` would become the exec target. |

### Task 4: Driver `--detach` (D6)

**Files:** `plugins/cc-codex-triage/scripts/codex-thread.sh`, `plugins/cc-codex-triage/commands/review.md`, `plugins/cc-codex-triage/commands/plan.md`; test: `tests/driver-regression.sh`.

- [ ] Flag parse `--detach`; combined with `--oneshot` → usage error. On `--detach`: write stdin prompt to `mktemp` file + create `READY_FILE=$(mktemp)`; pick isolator: `command -v setsid` → `setsid bash -c 'echo $$ > "$READY"; exec bash "$0" <args minus --detach>'`; else `command -v python3` → `python3 -c 'import os,sys; os.setsid(); open(sys.argv[1],"w").write(str(os.getpid())); os.execvp(sys.argv[2], sys.argv[2:])' "$READY_FILE" bash "$0" <args minus --detach>` — **no `--` separator** (with `-c`, `sys.argv[0]` is `-c`, so `--` would become the exec target); else stderr message + **exit 8** (documented next to 4/5/6/7). Child stdin `< "$PROMPT_TMPFILE"`, stdout/stderr `>> "$STATE_DIR/${THREAD}.detach-output"`.
- [ ] **Readiness handshake:** parent polls `$READY_FILE` for a PID (bounded, 5s, 0.1s steps); got one → print `DETACHED pid=<pid> output=<thread>.detach-output — poll the thread log for the next 'round=' header`, exit 0; timeout → kill the spawn if any, report failure, exit nonzero. Never print DETACHED before the child proved `setsid()` succeeded.
- [ ] Child cleanup: export `CC_CODEX_PROMPT_TMPFILE`/`CC_CODEX_READY_FILE` to the re-exec'd invocation; their removal joins the **combined `cleanup()`** from Task 1 (never a second `trap ... EXIT`). Test asserts prompt file, ready file, `OUT_FILE`, and `JSONL_FILE` are all gone after the child exits.
- [ ] Thread `.log` marker contract untouched — the child appends rounds/replies exactly as a foreground run; only raw stdout/stderr goes to `<thread>.detach-output` (named to avoid the `<t>.detach` thread-name collision — dots are legal in thread names per the driver regex, line ~70).
- [ ] `review.md`/`plan.md` `--background`: recommend `--detach` + poll the thread log for the next `round=` header (foreground Bash call returns instantly); keep `run_in_background` as the documented fallback with its reaping caveat.
- [ ] Regression tests: (t1) stub with 2s sleep, `--detach` → parent returns <1s AFTER the ready handshake with the DETACHED line; poll until the thread log holds the stub reply; rounds bumped exactly once; prompt+ready tmpfiles gone; sidecar exists. (t2) **kill-survival**: launch `--detach` from a wrapper that is itself session-isolated (same isolator helper — the regression harness stays outside the killed group), `kill -TERM -<wrapper pgid>` after parent exit, assert the reply still lands. (t3) no setsid AND no python3 on PATH → exit 8, no state written, no orphan tmpfiles. (t4) **python-path positive test**: PATH with setsid hidden but python3 present (works on Linux CI too) → detach succeeds via the python isolator, handshake completes, reply lands.
